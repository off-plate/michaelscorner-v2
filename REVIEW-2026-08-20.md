# Michael's Corner: design review, 20 Aug 2026

Reviewed against the rules we now actually have, rather than taste:

- `.claude/design/DESIGN.md`, the anti-slop canon and the navigation minimums
- `web-ship/references/lessons.md`, the failure catalogue paid for by 247 Car Rental,
  the Durres gym build and Blast & Burn
- `web-design-guidelines`, the Vercel Web Interface Guidelines
- `.claude/design/design-log.md`, what each project has already spent

Method: measured in a real browser at 390, 768, 834, 1440 and 2560, both themes, plus a
component-system audit and an interface-guidelines audit. Every finding below was verified
by hand. Nothing here is a guess.

---

## Verdict

The **look** is in good shape. The **system underneath it is not**, and that is the same
failure that cost four rounds on 247 Car Rental. Nothing on this list is a redesign. It is
one broken-in-the-browser bug, one rule the site breaks that you wrote yourself, and a pile
of duplication that will make every future request cost five edits instead of one.

Two of the findings are mine, made during this session. They are marked.

---

## What is genuinely good, and should not be touched

- No horizontal overflow at any width. `scrollWidth == viewportWidth` on every page tested.
- The mobile drawer works. Hamburger present, desktop nav correctly hidden, no clipping.
- One container system. `--shell: 1200px`, no page defines its own width (one exception, below).
- The receipt component, the corner-bracket hover, and the dot-matrix icons are the site's
  real signature and they are used with restraint.
- Fonts preload correctly with `font-display: swap`. Zero external origins.
- No `transition: all`, no zoom-disabling viewport, no `<div onClick>`, no gradients on
  heroes or buttons, no glassmorphism, no bento grid, no three-tier pricing.

## 1. Blockers: broken in the browser right now

### 1.1 The pack-card hover is inert, and the focus ring is gone. **My regression.**

`library.html:60` and `build.mjs:158`

```css
.pack-card:hover, .pack-card:focus-visible{ background:var(--green-pale); border-color:var(--green); outline:none; }
```

`--green-pale` is **defined nowhere**. I deleted the token earlier this session when you
called out the wrong sage, and I fixed only one of the two rules that used it. So the
background declaration is dropped, the hover changes only the border, and `outline:none`
removes the keyboard focus ring and replaces it with nothing visible. This affects the eight
pack cards, which are the library's primary entry points.

Fix: `var(--sage)`, and drop `outline:none` or give focus its own visible treatment.

### 1.2 The same `outline:none` pattern on every prompt row

`build.mjs:145` (`.rlink`), `build.mjs:298` (`.lrow`), `library.html:47`

Focus is styled identically to hover and the outline is removed. That is the entire
prompt-navigation surface across eight pack pages plus the search results. A keyboard user
cannot see where they are.

### 1.3 A blinking cursor that ignores reduced motion, on 64 pages

`build.mjs:392`

```css
.term-body .cur{ ... animation:mc-cur 1s steps(1) infinite; }
```

No `prefers-reduced-motion` guard. The template reads a `reduce` variable at `build.mjs:475`
but both branches at `:489`/`:490` are identical, so it does nothing. This is on the
highest-traffic content type on the site.

## 2. The site breaks your own navigation minimums. **Partly my regression.**

`DESIGN.md` states, as a floor and not a preference:

> Desktop nav items: **16px minimum**. **44px minimum hit height**, desktop included.
> **20px minimum gap** between items.

Measured at 1440px:

| Rule | Required | Actual |
|---|---|---|
| Font size | 16px min | **15px** (and 13px below 1200px) |
| Hit height | 44px min | **39px** |
| Gap between items | 20px min | **2px** |

I caused this when I shrank the nav to fit the seven sentence labels you chose.

**The good news: your labels fit at the correct minimums.** I measured it. At 16px type,
20px gaps and 12px vertical padding, the seven labels need **1070px** and the shell gives
**1088px**. It fits, with a 49px hit height and 18px to spare.

The one caveat: 1088px is the widest the nav ever gets, so below roughly 1210px viewport it
will need to wrap to two rows or hand over to the burger earlier. That is a decision, not a
problem.

## 3. The expensive class: one job, many components

This is the 247 Car Rental failure repeating. None of it is visible in a screenshot, which
is exactly why it survived.

### 3.1 Four components for "a clickable card"

| Class | Defined | Used |
|---|---|---|
| `.card` | `styles.css:364` | **nowhere** (dead) |
| `.hcard` | `index.html:42` | home |
| `.tcard` | `tools.html:46` | tools |
| `.pack-card` | `build.mjs:156` | library |

`styles.css:363` even documents the defect in its own comment: *"cards (baseline; pages
restyle via their own css)"*. And `shared.js:124` keeps a **seventh copy of the roster** as a
hardcoded selector string, which lists the dead `.card` and omits `.pcard`, `.proj-tile` and
`.feature`, so those three never get the site's signature corner hover.

### 3.2 `.vcard` is defined twice under one name, and has already drifted

`index.html:64` vs `channel.html:60`: width `332px` vs `314px`, `h3` `17px` vs `18px`, `p`
`13.5px` vs `14px`. This is the homepage-card-versus-listing-card bug, this time wearing the
same class name.

### 3.3 The one-edit test, with real numbers

- *"Make every primary button orange"*: **42 rule-sets across 12 files.**
- *"Make every card border green"*: **21 rule-sets across 11 files.**
- *"Change the card corner radius"*: **67 literal edits, 15 files.** There is no `--radius`
  token, even though `styles.css:3` states "Max radius 4px" as law. It has already drifted:
  `bill.html:31` uses 4px where the other twenty cards use 2px.
- *"Change every card hover"*: **9 rule-sets, four different treatments**, and three cards
  have no hover at all.

### 3.4 The seven tool pages are one page copied seven times

21 rule-sets are byte-identical across all seven `tools/*.html`, and three have already
drifted: `.t-pitch` is `58ch` in four files and `60ch` in three; `.face` grid is reversed in
`should-you-automate.html:29`; `.reset` lost a property between two copies.

`styles.css:94-100` then patches all seven from the outside to fake the green hero. That is a
patch over the duplication, not a merge.

### 3.5 Dead CSS

Roughly **55 of 433 lines (13%)** of `styles.css` is unused, including the entire `.reading`
layout system, `.pullquote`, `.sage-panel`, and a dead `.band-green` twin that sits one
dash away from the live `.band--green` and will be grabbed by mistake.

### 3.6 `404.html` is outside the system entirely

It never loads `styles.css` and redefines `:root` with its own token names (`--accent` is the
brand orange under a second name). Every brand change silently skips this page.

## 4. Interface guidelines

Ranked by real user impact.

1. **No skip-to-content link on any page.** Nine links to tab through before content, on ~80 pages.
2. **Search and filter results are silent.** `channel.html:127`, `tools.html:112` rebuild on
   every keystroke with no `aria-live`, including the "no matches" state. `library.html:113`
   already does this correctly, so the pattern exists in the codebase.
3. **Copy confirmations are silent.** `shared.js:40` mutates the button label only. Copy is
   the core interaction of the whole site.
4. **Tap targets under 44px everywhere.** Measured 15 to 29 per page at every width: nav 39px,
   footer links 23px, `head-cta` 23px, `pcard-open` 22px, `backlink` 22px, chips 36px,
   paddles 40-42px, and `.reset` at ~18px in two calculators.
5. **`icons.js` ignores `prefers-reduced-motion` entirely** (`icons.js:387`), and animated dot
   icons loop forever.
6. **Portraits ship with no `width`/`height`** (`index.html:122`, `about.html:88`), causing
   layout shift on the two most-visited pages. `assets/mark.svg` likewise on every page.
7. **Heading level skips.** `about.html` goes `h1` straight to `h3`. Every generated prompt
   page and pack page does the same (`build.mjs:440`, `build.mjs:327`).
8. **Decorative canvases missing `aria-hidden="true"`** throughout.
9. Small stuff: `touch-action: manipulation` appears nowhere; no `overscroll-behavior` on the
   five horizontal carousels or the mobile drawer; `...` instead of `…` in two tool
   placeholders; straight quotes in `start.html:141` and `bill.html:88` where the rest of the
   site uses curly.

## 5. Composition

- **The homepage tool card is a stripped copy of the tools-page card.** `.hcard` holds only a
  title and "Open the tool", so roughly 40% of it is empty air, while `.tcard` on the tools
  page has a tag, a designation, a description and a spec hint. Same job, one of them gutted.
- **The library grid strands a cell.** `.pack-grid` uses
  `repeat(auto-fill, minmax(340px, 1fr))`, which gives three columns at 1088px, so eight
  cards land 3+3+2 with a hole. `lessons.md` warns about this exact pattern: auto-fit/auto-fill
  cannot guarantee a count, state the count per breakpoint.
- **Closing green bands run two-thirds empty** on library, tools and channel. The channel one
  earns its height because it carries a Subscribe button; the other two do not.
- **The tools page repeats its own hero** as the closing band heading.
- **11px type** on tags, designations and hints across tools, library and the receipt stamp.

---

## 6. Recommended order

Each step is independent and safe to stop after.

1. **Fix what is broken** (§1). Three small edits: `--green-pale` to `--sage`, restore focus
   rings, guard the blinking cursor. Roughly ten minutes.
2. **Fix the nav to your own minimums** (§2). Your labels already fit; decide the sub-1210px
   behaviour.
3. **Add the tokens the system is missing**: `--radius`, and one hover treatment. This is what
   turns "five edits" into "one edit" for everything after it.
4. **Merge the four card components into one** with modifiers, and delete the dead 13% of
   `styles.css`. Then update `shared.js:124` to stop keeping its own roster.
5. **Lift the seven tool pages' shared CSS into `styles.css`.** Highest volume, already
   drifting.
6. **Accessibility pass** (§4), starting with the skip link, the live regions and the tap
   targets.
7. **Composition** (§5), last, because most of it resolves once the cards are one component.

Steps 3 to 5 are the ones that stop the next request costing five edits. Everything before
them is repair; everything after is polish.
